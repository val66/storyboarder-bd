# Architecture and naming

> The README lists the files. This document gives the **rules**: what is allowed to go where, and
> how things are named.

## Rule #1 — all application code lives in `src/*.js`

`main.js` and `preload.js` are the Electron process files: window, disk access, IPC. **They are
never touched for an application feature.**

This rule has a concrete, non-obvious consequence: the renderer cannot read `package.json`, which
would require an IPC channel. Hence `src/version.js`, generated by `tools/bump-version.mjs`. When a
piece of information "belongs" to the main process, the right answer is most often to push it down
as a generated file, not to open a channel.

`src/app.js` is a one-line stub that imports `events.js` — the real entry point.

## Rule #2 — circular imports are broken by callback injection

Modules have crossed needs: `scene3d.js` must redraw the page, `draw.js` must update the side
panel, `i18n.js` must refresh the tree. A direct import would create a cycle.

The pattern used: the module exposes a `set*Callbacks()` that `events.js` calls at startup.

```js
setScene3DCallbacks({ drawCurrentPage, refreshCameraSliders, renderSideCameraGizmo });
setDrawCallbacks({ canvas, ctx, applyZoom, updateSidePanel, … });
setI18nCallbacks(onUpdateSidePanel, onRenderTree);
setIOCallbacks(onRenderAll, onRenameVolume, onRenameScene, onCloseSettings);
setPersonaEditorCallbacks({ buildPersonaPositionOptions });
```

The last one is the smallest possible case, and worth reading as the template: extracting
`persona-editor.js` out of `events.js` left **one** upward dependency — refreshing the Character
modal's pose list after the library changes. One function. Importing it would have closed the cycle
for the sake of a single call; injecting it costs four lines and keeps the graph acyclic.

**Textbook case.** `tracéBBox` was defined in `events.js` and called from `scene3d.js`. An import
would have looped; without an import, the call raised a `ReferenceError` on the first render of a
Page containing a Path — and no Panel could be selected any more. The right answer was neither the
import nor the callback: the function was **pure**, its place was in `utils.js`.

Hence the order of preference: pure function in `utils.js` → injected callback → direct import only
if the graph stays acyclic.

## Rule #3 — shared state goes through `S`

`src/state.js` exports an object `S` carrying the application's mutable state (`S.selectedId`,
`S.modalTarget`, `S.buildTool`, `S.tomes`…). Modules read and write it, which avoids dozens of
parameters passed from hand to hand.

Accepted trade-off: a modification of `S` is invisible in the signatures. When a function depends on
`S`, say so in its comment.

## Naming

The rules below concern the **code**. They do not apply to persisted data, which follows its own
logic — see `docs/persisted-data.md`.

### `3D` suffix

Every function or constant that works in 3D world units carries it: `tracéWallHeight3D`,
`GROUND_Y_DEFAULT_3D`, `wallOpeningWorldPosOnTracé3D`. About a hundred functions carry it today. It
is what makes a world computation distinguishable at a glance from a canvas computation — the
costliest confusion in this project.

### `ensure*` prefix for functions that create on demand

`ensurePersonaRigEntry3D`, `ensureWallRenderEntry3D`, `ensureElementWorldPos3D`: they return the
existing thing, or build it if missing. They used to be called `get*`, which suggested a plain read
while they populate a cache and add to the scene.

Reserve `get*` for what modifies nothing.

### No arbitrary underscore prefix

Leading `_` were removed from identifiers where they meant nothing. They remain on local variables
in a dense scope (`_tracéPos`, `_tmHoles`) where they mark a computation temporary — not any kind of
privacy.

### Language

**Comments and identifiers: English.** The eleven modules of `src/` were translated (#209-219).

**Domain terms: French**, because they are in the data and in the interface. `tracé`, `Parois`,
`Muret`, `Case`, `Tome`, `Planche`. Translating them would create a third vocabulary between the
project file, the interface and the code.

`tracé` / `Tracé` / `TRACÉ` is explicitly protected: it is translated nowhere, not even in a
comment.

**`docs/` documentation: bilingual.** Each document exists as `name.md` (English) and
`name.fr.md` (French), mirroring `README.md` / `README.fr.md`. The French version is the one the
decisions were originally written in; both are kept in step. The built-in manual
(`src/help-content.js`) is bilingual too.

## When a change is visible to the user

Update together, in the same commit:

- `README.md` **and** `README.fr.md`
- the built-in manual `src/help-content.js`, in **both** languages
- `src/i18n.js` if a label is added

This is not required for internal work: refactoring, tests, comment translation.
